# 棉卫士上手指南

目标：先用你自己的棉花数据完成去重、短训检查和 YOLOv8n 基线；之后再验证鲁棒训练与边缘部署。原始数据、训练权重和缓存都保留在本地，不提交到 GitHub。

## 1. 创建环境

当前开发机已验证 RTX 5060 Laptop、8GB 显存、PyTorch 2.14 + CUDA 13。CUDA 版本不匹配时，按 PyTorch 官网给当前驱动选版本。

```bash
cd cotton-doctor
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-cu130.txt
```

验证：

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
cotton-doctor --help
```

## 2. 生成数据检查和无精确重复划分

把数据解压到本地一个目录，参数用引号包住，避免空格/中文路径被拆开：

```bash
cotton-doctor audit "/path/to/棉花数据集" --output data/processed/audit
cotton-doctor prepare "/path/to/棉花数据集" --output data/splits/exact
cotton-doctor prepare-grouped "/path/to/棉花数据集" --output data/splits/grouped-v2
```

WSL示例：

```bash
cotton-doctor prepare-grouped "/home/ykkkyi/yky/falcons/det_cotton_leaf_disease_yolo棉花病虫害数据集4280-1201-616 yolo8类" --output data/splits/grouped-v2
```

精确去重是中间检查；训练使用 `data/splits/grouped-v2/data.yaml`。新划分为训练 3,801、验证 1,085、测试 544 张，共 2,828 个视觉候选组。打开 `data/splits/grouped-v2/split-report.json` 和 `near-pairs.csv` 检查分组；公开的相对路径、文件哈希与组 ID 清单在 `reports/`。命令不移动、覆盖或删除原图。类别名称、同株不同角度、错框和漏标仍需复核。

## 3. 用一轮做冒烟测试

在正式长训前，确认权重能下载、数据路径可读、GPU显存够用：

```bash
cotton-doctor train --data data/splits/grouped-v2/data.yaml --model yolov8n.pt --epochs 1 --imgsz 640 --batch 8 --device 0 --workers 4 --name smoke_yolov8n
```

冒烟测试只验证软件链路，不是可报告的模型结果。若显存不足，先将 `--batch` 改为4或2。

## 4. 正式基线

冒烟测试成功且数据划分通过人工复核后：

```bash
cotton-doctor train --data data/splits/grouped-v2/data.yaml --model yolov8n.pt --epochs 120 --imgsz 640 --batch 8 --device 0 --workers 4 --seed 42 --name E0_grouped_yolov8n_seed42
```

训练日志和权重保存在 `runs/E0_grouped_yolov8n_seed42/`，目录已被 Git 忽略，不会上传。保存当前代码版本和数据清单哈希，便于复现。

## 5. 验证后再测最终测试集

训练期间只用验证集查看曲线、逐类结果和漏检样例：

```bash
cotton-doctor evaluate runs/E0_grouped_yolov8n_seed42/weights/best.pt --data data/splits/grouped-v2/data.yaml --split val
```

模型、置信度/NMS阈值和部署设置冻结以后，才加 `--split test --allow-test` 做最终测试。测试结果不能再用来选配置。

## 6. 本地网页

当前网页版支持图片上传、浏览器拍照、标框图显示以及 JSON/CSV/图片下载。放入你本地训练好的权重后启动：

```bash
mkdir -p weights
cp runs/E0_grouped_yolov8n_seed42/weights/best.pt weights/best.pt
uvicorn cotton_doctor.web:app --host 127.0.0.1 --port 8000
```

浏览器打开 `http://127.0.0.1:8000`。默认 CPU 推理；可在启动前设置 `COTTON_DEVICE=0` 使用显卡。图片与四帧视频已实测通过；USB 相机需在能访问相机的系统中实测，WSL 可能需要相机转发。TensorRT 和实际边缘设备结果尚未完成。

## 7. 顺序完成两种基线与部署检查

当前机器可直接使用已创建的 `.venv`，不必重装。安装其他环境时，ONNX 工具需要 `python -m pip install -e '.[export]'`。

```bash
python scripts/run_baseline_suite.py --plan
python scripts/run_baseline_suite.py
```

自动流程：YOLOv8n 训练/验证 → YOLO11n 训练/验证 → GPU/CPU 端到端计时 → 合成验证压力集 → 按验证 mAP50–95 选择基线 → ONNX 导出/数值检查 → 汇总报告。最终测试集不会在这个流程里评测。

进度在 `runs/baseline-suite/state.json`；各步骤日志在 `runs/baseline-suite/logs/`。若已有训练正在运行，添加 `--wait-pid <训练进程号>`，避免重复任务。可用 `cotton-doctor train --resume runs/<运行名>/weights/last.pt` 恢复意外中断的训练。

流程完成后生成 `reports/baseline-comparison.json` 和 `.md`，选择出的基线保存在 `weights/best.pt` 与 `weights/best.onnx`。添加 `--publish-reports` 会只提交并推送这两份汇总报告；数据、图片、权重和逐帧结果仍在本地。若已有其他暂存改动或 Git 推送失败，报告保留在本地，并在状态文件记录失败。

```bash
cotton-doctor predict weights/best.pt --source /path/to/cotton.mp4 --output runs/predict/video
cotton-doctor predict weights/best.pt --source 0 --max-frames 300 --output runs/predict/camera
```

需要练习的知识和每步验收标准见 [完整方案](project-plan.md) 与 [知识路线](learning-path.md)。创新增强、蒸馏和真实田间/边缘设备实验在基线与误差分析之后推进，不能把已完成的工程链路写成已经取得算法创新收益。
